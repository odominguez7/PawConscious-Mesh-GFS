Wire into Vertex AI Agent Engine (ADK)

The documented ADK path for consuming a remote A2A peer is RemoteA2aAgent. PawConscious publishes a standard A2A v0.3 agent card, so any ADK 2.0 host can wrap it and call verify_claim as a sub-agent.

# 1. PawConscious publishes its agent card at:
#    /.well-known/agent-card.json

# 2. Wrap it as a remote A2A sub-agent in your ADK host
from google.adk.agents import LlmAgent
from google.adk.agents.remote_a2a_agent import RemoteA2aAgent

pawconscious = RemoteA2aAgent(
    name="pawconscious",
    agent_card="/.well-known/agent-card.json",
)

shopper = LlmAgent(
    name="shopper",
    model="gemini-2.5-pro",
    sub_agents=[pawconscious],
    instruction="Before recommending any pet supplement, call pawconscious with the product URL and gate on a PASS verdict.",
)

Verify a signature offline

The bundle is canonical-JSON, signed with the Ed25519 key advertised in /.well-known/did.json. Verify with 6 lines:

from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PublicKey
import base58, base64, httpx, json

did = httpx.get("/.well-known/did.json").json()
pk_multibase = did["verificationMethod"][0]["publicKeyMultibase"]
pk_bytes = base58.b58decode(pk_multibase[1:])[2:]  # strip multibase 'z' + 0xed01 prefix
pub = Ed25519PublicKey.from_public_bytes(pk_bytes)

# canonical_json = bundle minus the signature field, no whitespace
pub.verify(base64.b64decode(bundle["signature"]), canonical_json.encode())
# Raises InvalidSignature if tampered. Else: trust the bundle.

Errors

HTTP responses currently emitted by /a2a/v1/*. The mesh's internal failure modes surface through the task envelope, not the transport. A 200 with status: "failed" in the task is the common shape for agent-stage errors.

HTTPMeaningRecover
200Task fetched (GET), including replay of an idempotent submission.Read output; check status for agent-stage failures.
202Task accepted async. Body has task_id. Idempotent re-submit of the same key also returns 202 with the original id.Poll GET /a2a/v1/tasks/get/{task_id}.
400Semantic error. For example, missing product_url on a verify_claim envelope, or skill+input shape mismatch.Check shape against the A2A v0.3 example above.
401Missing or invalid X-API-Key.Add the demo key demo-key-2026-06 for hackathon access.
404Unknown skill, unknown task_id, or expired task.Re-submit the verify_claim task with a known skill.
409Returned by /a2a/v1/tasks/cancel/{task_id} when the task is already in a terminal state (completed / failed / canceled).Don't retry. The task is already done. Fetch it via /a2a/v1/tasks/get/{task_id}.
422FastAPI validation. Malformed JSON body, missing required field, or wrong type. Distinct from 400 (semantic) and 404 (unknown skill).Response body has the specific field path. Fix the payload and re-submit.
5xxCloud Run / upstream Vertex AI / Firestore unavailability.Retry with exponential backoff.

Per-skill 403 and rate-limit 429 / Retry-After are on the v0.2 roadmap once a real rate-limiter and per-key authorization land.
