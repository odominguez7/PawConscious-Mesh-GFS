7 Agents · 3 StagesShape

Stage 1 (reasoning mesh, 5 agents): claim-extractor first, then evidence-grader · vet-rubric · compliance fan out per claim via asyncio.gather, then auditor merges. Stage 2: Ed25519 sign + chain anchor. Stage 3 (post-sign, 2 agents): cert-composer + adversarial second-opinion run in parallel.

ADK 2.0Orchestration

Used by claim-extractor (google.adk.agents.LlmAgent). The other 6 agents call google.genai SDK direct for v0.1 deterministic latency. ADK ParallelAgent + SequentialAgent wrappers are documented as the Phase 4 Vertex AI Agent Engine deployment surface.

Gemini 2.5Reasoning

2.5 Pro for claim extraction, evidence grading, vet rubric, compliance mapping, cert composer, and adversarial Second Opinion (6 agents). 2.5 Flash for the deterministic auditor (1 agent). Most calls use temperature=0.0; Second Opinion uses 0.3 for adversarial breadth.

GroundingTruth

Vertex AI Search grounds the compliance agent against a public-redistributable regulator corpus (FTC 16 CFR §255 · AAFCO PF7 · NASC). Google Search grounding via google.genai powers the Second Opinion's 4 stress tests (court · regulator · consensus · public skepticism). Vet-panel is intentionally prompt-only — no licensed handbook ingest.

A2A v0.3Interop

Public agent card at /.well-known/agent-card.json. Async lifecycle: /tasks/send → poll /tasks/get. External ShopperAgent (separate Cloud Run service, MIT) consumes it end-to-end — no third-party integrations claimed.

MCP + CitationsEvidence

BioMCP (21 tools, MIT) → live PubMed / Europe PMC retrieval. Semantic Scholar Graph API batch enriches every paper with citation + influential-citation counts (public surface of AI2 Asta). The auditor verifies PMID format and direction match before signing.

Cloud Run + FirestoreRuntime

Mesh API + ShopperAgent are independent Cloud Run services (scale-to-zero, Artifact Registry images). Firestore holds the append-only transparency log: chain_anchor = sha256(bundle_hash + ":" + (prev_hash or "genesis")). Public head at /pcec/v0/chain/head.

How it works

One URL in. A signed evidence bundle out.

01 · Submit
Paste a product page URL
Any pet supplement PDP. Firecrawl fetches the live page; the claim-extractor parses every health claim on the label.
POST /a2a/v1/tasks/send { "skill": "verify_claim", "input": { "product_url": … } }
02 · Mesh
Seven agents · three stages
Stage 1 — reasoning mesh: claim-extractor (ADK + httpx) runs first, then for every claim the orchestrator fans out evidence-grader (BioMCP → PubMed + Semantic Scholar) · vet-rubric (prompt-only) · compliance (Vertex AI Search) in parallel, then auditor (Gemini 2.5 Flash) merges. Stage 3 — adversarial: after signing, cert-composer renders the branded HTML and second-opinion (Gemini + Google Search grounding) runs 4 stress tests against the conclusion.
claims = await extract_claims(url) for claim in claims: e, v, c = await asyncio.gather( grade(claim), vet(claim), comply(claim)) audit = await audit_bundle(e)
03 · Sign
Ed25519 + chain anchor
Bundle merged, signed against the mesh DID, appended to Firestore log. Any A2A v0.3 agent can fetch and verify.
GET /a2a/v1/tasks/get/{id} → { bundle_hash, signature, chain_anchor, output: {…} }
The artifact

Not a badge. A signed document the agentic shelf can verify.

Every claim on the label is mapped to citations, scored by a rubric, checked against the FTC endorsement guide, and cryptographically signed. The bundle is machine-readable Pydantic JSON over A2A v0.3 (JSON-LD evolution on the PCEC v0.2 roadmap), with a SHA256 chain anchor anyone can audit.

Any A2A v0.3-compatible agent (e.g. our reference ShopperAgent in the repo) can fetch the bundle, verify the signature, and use it to surface the product as evidence-backed. No third-party integrations claimed — Amazon Rufus, Perplexity Shopping, etc. are the use case, not current integrations.
